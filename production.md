## 1. What you are deploying

One host running, behind a single reverse proxy and a single identity provider:

| Component | Containers | Notes |
| --- | --- | --- |
| **Workcenter** | 1 | Shell + broker, built from this repository |
| **FileBrowser Quantum** | 1 | Files, with the OnlyOffice integration |
| **ONLYOFFICE Docs** | 1 | Document editing |
| **Zulip** | 5 | `database`, `memcached`, `rabbitmq`, `redis`, `zulip` |
| **Mailcow** | ~18 | Postfix, Dovecot, Rspamd, ClamAV, MariaDB, Redis, Unbound, nginx, SOGo, watchdog, … |
| **Authentik** | 3 | `postgresql`, `server`, `worker` (plus an LDAP outpost if used) |
| **Traefik** | 1 | Ingress, TLS, dashboard |

Six public hostnames, all TLS-terminated at Traefik:

```
example.com               Workcenter
filebrowser.example.com   FileBrowser Quantum
auth.example.com          Authentik
mail.example.com          Mailcow UI + SOGo
chat.example.com          Zulip
traefik.example.com       Traefik dashboard (workspaceadmin only)
```

## 4. `setup.sh` — the contract

`setup.sh` lives in the repository root. It is **idempotent**: running it twice must change nothing on
the second run, and running it a third time must still change nothing.

### 4.1 Purpose

Take a bare host with Docker and correct DNS to a fully deployed, TLS-terminated, OIDC-protected
Workcenter stack — with exactly **one** manual step, which is configuring providers in the Authentik
Web UI.

### 4.2 Interface

```bash
./setup.sh [options]

Options:
  -h, --help              Show usage and exit
  -y, --yes               Assume "yes" for confirmations (does not skip required values)
  -n, --non-interactive   Never prompt; read everything from the environment or existing .env files.
                          A missing required value is a fatal error.
      --base-domain DOMAIN
                          Set the base domain without prompting
      --skip-pull         Do not pull images
      --skip-up           Configure only; do not bring the stack up
      --force             Reconfigure files that already exist (backs them up first)
  -v, --verbose           Trace command execution
```

### 4.3 Guarantees

| Ref | Guarantee |
| --- | --- |
| P-1 | **Idempotent.** Existing folders are never emptied, existing `.env` values are never overwritten without `--force`, and existing volumes are never touched. |
| P-2 | **Non-destructive by default.** Nothing is deleted. Every destructive action requires explicit confirmation or `--force`. |
| P-3 | **Fail-fast.** `set -Eeuo pipefail` plus an `ERR` trap that prints the failing line and command. |
| P-4 | **Non-interactive capable.** Every prompt has an environment-variable equivalent; `--non-interactive` never blocks. |
| P-5 | **No secrets echoed.** Generated and entered secrets are masked in all output and never written to logs. |
| P-6 | **Resumable.** Stopping at any prompt and re-running continues from the detected state. |
| P-7 | **Never edits upstream files.** Mailcow's `docker-compose.yml`, `generate_config.sh` and `update.sh` are untouched. |
| P-8 | **Convergent.** Ends with a per-service health report and a non-zero exit code if any service failed to become healthy. |

### 4.4 Required behaviour, in order

1. **Create the application folders** if missing: `Filebrowser/`, `Zulip/`, `Mailcow/`, and — on
   demand — `OnlyOffice/`, `Authentik/`, `Traefik/`.
2. **Provision each application's files** if missing:
   * **Mailcow** — clone `mailcow-dockerized` and run **its own** `generate_config.sh` with the
     variables pre-set so it never prompts (see [§5.2](#52-stage-b--application-file-provisioning)).
     Mailcow is downloaded, not templated, because its installer owns `mailcow.conf`.
   * **FileBrowser Quantum** — write `Filebrowser/config.yaml` from the repository template and
     `.env` with generated secrets. The image is pulled; no source build.
   * **Zulip** — write `Zulip/compose.yaml`, `Zulip/compose.override.yaml`, `Zulip/.env` and the five
     secret files. The image is pulled; no source build.
3. **Detect Traefik.** If it is already running, adopt it (join `proxy`, do not deploy a second proxy).
   If not, create `Traefik/` and add it to the stack.
4. **Ask for the base URL** and derive the six hostnames; write them into every `.env`.
5. **Skip the `.env`/OIDC checks for anything this run created** — there is nothing to check yet — and
   go straight to the Authentik deployment question.
6. **Resolve OIDC**, following the branch logic in [§5.5](#55-stage-e--oidc-resolution).
7. **Bring the stack up** with `docker compose up -d` and wait for health.
8. **Report** per-service health and exit accordingly.

### 4.5 The stop message

Whenever `setup.sh` stops because Authentik is not yet configured, it prints **exactly** this — the
wording is part of the contract and is reproduced in [`OIDC.md` §8.6](./OIDC.md#86-the-stop-message):

```text
Create required OIDC application and provider per OIDC.md in authentik.
Once complete rerun setup.sh to input the .env variables as necessary for Workcenter.
```

## 5. What `setup.sh` does, stage by stage

### 5.1 Stage A — Folder check

```bash
for app in Filebrowser Zulip Mailcow; do
  if [[ -d "${app}" ]]; then
    ok "${app}/ exists"
  else
    info "${app}/ missing — creating"
    mkdir -p "${app}"
    CREATED+=("${app}")          # recorded: skips the .env/OIDC checks for this app later
  fi
done
```

Anything in `CREATED` is exempt from the configuration checks in stage E — a freshly created folder
cannot already contain configuration, so asking about it would be nonsense.

### 5.2 Stage B — Application file provisioning

**Mailcow** (downloaded and prepared by its own installer):

```bash
cd Mailcow
export MAILCOW_HOSTNAME="mail.${BASE_DOMAIN}"
export MAILCOW_TZ="${TZ:-Etc/UTC}"
export MAILCOW_BRANCH="master"
export MAILCOW_DBPASS="$(openssl rand -hex 24)"
export MAILCOW_DBROOT="$(openssl rand -hex 24)"
export MAILCOW_REDISPASS="$(openssl rand -hex 24)"
export SKIP_CLAMD="${SKIP_CLAMD:-n}"
export FORCE="y"                 # suppresses the interactive IPv6 daemon.json prompt
./generate_config.sh
# then, because Traefik terminates TLS for mail.example.com:
sed -i 's/^HTTP_REDIRECT=.*/HTTP_REDIRECT=n/'                 mailcow.conf
sed -i 's/^SKIP_LETS_ENCRYPT=.*/SKIP_LETS_ENCRYPT=y/'         mailcow.conf
sed -i 's/^AUTODISCOVER_SAN=.*/AUTODISCOVER_SAN=n/'           mailcow.conf
sed -i 's/^HTTP_BIND=.*/HTTP_BIND=127.0.0.1/'                 mailcow.conf
sed -i 's/^HTTPS_BIND=.*/HTTPS_BIND=127.0.0.1/'               mailcow.conf
```

| Ref | Note |
| --- | --- |
| P-9 | `HTTP_REDIRECT=n` is **mandatory**. The generator writes `y`, and with `y` the only listener on `HTTP_PORT` is a 301 redirect — so Traefik → `http://nginx:8080` returns `301 https://mail.example.com` and loops forever. Mailcow's own Traefik guide omits this step. |
| P-10 | `FORCE=y` is required for a fully non-interactive run; without it the generator may ask about rewriting the Docker daemon's IPv6 configuration. |
| P-11 | Ports **cannot** be unpublished from an override file — Docker concatenates `ports` lists. `HTTP_BIND`/`HTTPS_BIND` is Mailcow's supported mechanism, and the override supplies `expose` plus the `proxy` network. |
| P-12 | Never set `COMPOSE_FILE` in `mailcow.conf`: that file **is** Mailcow's `.env`. |
| P-13 | Never pass `-f` when driving Mailcow. Run `docker compose` from inside `Mailcow/` so the override auto-merges and `update.sh` keeps working. |

**FileBrowser Quantum** (templated, image pulled):

* Write `Filebrowser/config.yaml` from the repository template.
* Write `Filebrowser/.env` with `FILEBROWSER_JWT_TOKEN_SECRET` and `FILEBROWSER_ONLYOFFICE_SECRET`
  generated with `openssl rand -base64 32`, and the OIDC client ID/secret once known.
* Create `Filebrowser/data/` and `Filebrowser/office-cache/`.
* `chown 1000:1000` the data directory (the image runs as uid 1000).

**Zulip** (templated, image pulled):

* Write `Zulip/compose.yaml` pinned to `ghcr.io/zulip/zulip-server:<version>-0`.
* Write `Zulip/compose.override.yaml` with bind-mounted state, healthchecks for all five services,
  and Traefik labels.
* Generate the five `Zulip/secrets/zulip__*` files and the `zuliprc` bot credentials placeholder.
* Write `Zulip/.env` with `SETTING_*` scalars and a `ZULIP_CUSTOM_SETTINGS` block.

**OnlyOffice** (templated, image pulled): write `.env`, `compose.yaml` with the JWT secret matching
FileBrowser's `integrations.office.secret`, and the four bind-mounted directories.

### 5.3 Stage C — Traefik

```bash
if docker ps --format '{{.Image}}' | grep -q 'traefik'; then
  ok  "Existing Traefik detected — adopting it"
  PROXY_NETWORK="$(docker inspect "$(docker ps --filter ancestor=traefik --format '{{.ID}}' | head -1)" \
                   --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{"\n"}}{{end}}' | head -1)"
else
  warn "No running Traefik detected"
  ask_yn "Deploy Traefik as part of the Workcenter stack?" Y && deploy_traefik
fi
```

Adoption means: joining the existing proxy network and **not** deploying a second proxy. The network
name is detected, not assumed.

### 5.4 Stage D — Base URL

```text
?  What is the base domain for Workcenter (the root URL)? [example.com]
```

Then derived, printed, and confirmed. The derivation rule: the prefixes `filebrowser.`, `auth.`,
`mail.`, `chat.` and `traefik.` are applied to the **registrable domain**, so a base of
`work.example.com` yields `filebrowser.work.example.com`.

At the end of this stage every configuration file and compose file is complete. The only thing left is
OIDC.

### 5.5 Stage E — OIDC resolution

```text
⚠  OIDC configuration is incomplete.
?  Have you already created the required OIDC applications and providers in Authentik? [y/N]
```

| Answer | Script behaviour |
| --- | --- |
| **yes** | Create `Authentik/` in the Workcenter root for Authentik's own files, then prompt for every OIDC value into the correct `.env` and `config.yaml`, with a short descriptor per prompt. The prompts are specified verbatim in [`OIDC.md` §8.4](./OIDC.md#84-stage-d--authentik-deployment). |
| **no** *(default)* | Check whether Authentik is running on the host. If it is, offer to configure the values now. If it is not, offer to **deploy** Authentik: request the values needed to deploy it securely, generate the secrets, bring it up, and stop with the guidance message. If the user declines deployment, stop immediately with the same message and deploy nothing further. |

The prompt text for every value is normative and lives in
[`OIDC.md` §8](./OIDC.md#8-the-setupsh-prompt-contract). `setup.sh` and `OIDC.md` must never drift; a
change to one requires a change to the other in the same PR.

### 5.6 Stage F — Bring-up and health

```bash
docker compose up -d
./scripts/healthcheck-all.sh --wait --timeout 600
```

`healthcheck-all.sh` polls `docker compose ps --format json` until every service with a healthcheck is
`healthy`, or the timeout expires. On timeout it prints the failing services' last 50 log lines and
exits non-zero.

## 6. The deployment layout

```
workcenter/                          # the repository root == the deployment root
├── compose.yaml                     # root composition
├── compose.test.yaml                # deterministic profile for the E2E suite
├── setup.sh
├── .env                             # generated, gitignored
├── .env.example
├── scripts/
├── user-data/                       # Workcenter config + broker token store
├── Filebrowser/   .env  config.yaml  data/  office-cache/  compose.yaml
├── OnlyOffice/    .env  compose.yaml  data/  logs/  lib/  db/
├── Zulip/         .env  compose.yaml  compose.override.yaml  secrets/  data/  database/  rabbitmq/  redis/
├── Mailcow/       mailcow.conf  docker-compose.yml  docker-compose.override.yml  data/
├── Authentik/     .env  compose.yaml  data/{postgres,media,certs,templates}
└── Traefik/       .env  compose.yaml  traefik.yml  dynamic/  acme.json  certs/  logs/
```

| Ref | Rule |
| --- | --- |
| P-14 | Every application owns exactly one top-level folder; everything it writes lives inside it. |
| P-15 | Every volume is a bind mount of the form `./<AppFolder>/<subpath>:<container path>`. |
| P-16 | `.env`, `**/secrets/`, `**/data/`, `acme.json` and `*.local.yaml` are gitignored. |
| P-17 | Backup is a single `rsync` of the repository root (excluding `.git`), plus a database dump per stateful service. |

## 7. Networks, ingress and TLS

### 7.1 Networks

| Network | Created by | Purpose |
| --- | --- | --- |
| `proxy` | Traefik (external to the app composes) | Anything Traefik must reach |
| `internal` | the root compose | Service-to-service traffic |
| `mailcow-network` | Mailcow | Mailcow's internal traffic |

### 7.2 Traefik roles

```yaml
# Traefik/traefik.yml (static)
entryPoints:
  web:        { address: ":80" }
  websecure:  { address: ":443" }
  traefik:    { address: ":8080" }
providers:
  docker: { exposedByDefault: false, network: proxy }
  file:   { directory: /etc/traefik/dynamic, watch: true }
certificatesResolvers:
  le:
    acme:
      email: "${ACME_EMAIL}"
      storage: /acme.json
      httpChallenge: { entryPoint: web }
```

| Ref | Note |
| --- | --- |
| P-18 | **Both** `traefik.docker.network` (the per-service label) **and** `providers.docker.network` (the static setting) must be set. With either missing, Traefik "randomly picks" one of a container's networks — the single most common cause of a 502. This matters especially for `nginx-mailcow`, which joins both `mailcow-network` and `proxy`. |
| P-19 | Traefik's image has **no** `HEALTHCHECK`. Workcenter's compose defines one against `/ping` on the `traefik` entrypoint. |
| P-20 | The dashboard is exposed only at `traefik.example.com` behind Authentik forward-auth, restricted to `workspaceadmin`. Use `api.insecure=false` plus a router whose rule matches **both `/api` and `/dashboard`** with the `api@internal` service. Forward auth needs **two routers** — one for `/outpost.goauthentik.io/` at a **higher priority** than the application router — plus `maxResponseBodySize: 4194304`. |
| P-21 | **TLS options cannot be expressed as Docker labels** — Traefik documents `tls.options` as unsupported by label- and tag-based providers. Any TLS option, custom `serversTransport`, or forward-auth chain therefore belongs in the **dynamic file** provider under `Traefik/dynamic/`. |
| P-22 | Zulip's long-poll route needs response buffering **off** and extended read/idle timeouts. It does **not** need websocket handling; Zulip has no websockets. |
| P-23 | OnlyOffice's router must allow framing and set `accesscontrolalloworiginlist=*`; FileBrowser's router uses a security-headers middleware. These must not be shared. |
| P-24 | `acme.json` must be mode **600** (Traefik enforces this) and **cannot be shared between Traefik instances** — run exactly one. |
| P-25 | Let's Encrypt allows **5 certificates per exact identifier set per 7 days**. Set `tls.domains[0].main` and `.sans` so that several `Host()` rules collapse into one certificate instead of one certificate each. Wildcard certificates require the **DNS-01** challenge (for Cloudflare, the minimal credential is `CF_DNS_API_TOKEN` alone). |
| P-26 | A **404 from Traefik does not mean Traefik is absent.** Since Traefik v3.7.3 a malformed `$$` escape in a basic-auth label returns 404 rather than 401, so `setup.sh`'s detection must not rely on a 404. Use `docker ps` plus the `/ping` endpoint instead. |
| P-27 | Traefik's default `log.level` is **ERROR**, so an empty log is normal. Raise it deliberately when debugging, and pin the Traefik tag: `traefik.docker.allownonrunning` requires **v3.6+**. |

### 7.3 TLS

* Let's Encrypt via the `le` resolver and HTTP-01, stored in `Traefik/acme.json` (`chmod 600`).
* Renewal is automatic; Traefik reloads the certificate without a restart.
* For DNS-01, add the provider's credentials and switch `httpChallenge` to `dnsChallenge`.
* Mailcow's own ACME is disabled (`SKIP_LETS_ENCRYPT=y`) because Traefik owns certificates.
* If backend services need TLS, see [§12](#12-internal-tls-between-backend-services).

## 8. Starting, stopping and checking the stack

```bash
# Bring everything up
docker compose up -d

# Mailcow is driven from its own directory, with no -f flag
(cd Mailcow && docker compose up -d)

# Status and health
docker compose ps
docker compose ps --format 'table {{.Service}}\t{{.Status}}\t{{.Health}}'

# Mailcow status
(cd Mailcow && docker compose ps)

# Logs
docker compose logs -f workcenter
docker compose logs -f --tail=100 zulip

# Stop (keeps data)
docker compose down
(cd Mailcow && docker compose down)

# Restart one service
docker compose restart workcenter
```

> **Warning:** `docker compose down -v` deletes volumes. Workcenter uses bind mounts, so its data
> survives — but Mailcow's named volumes do **not**. Never run `down -v` in `Mailcow/` unless you
> intend to destroy mail.

## 9. Day-2 operations

| Task | How |
| --- | --- |
| Add a user | Create them in Authentik, add them to `workspaceusers`, and create their mailbox in Mailcow (or let Generic-OIDC auto-provision it) |
| Grant admin | Add them to `workspaceadmin`, then rerun `./setup.sh` so Zulip's out-of-band role sync runs |
| Revoke access | Remove them from `workspaceusers`; access ends at the next token refresh |
| Add a file source | Edit `Filebrowser/config.yaml` under `server.sources[]` (remember `config.defaultEnabled: true`), then `docker compose restart filebrowser` |
| Change the theme or language | Edit `user-data/conf.yml` and reload the shell |
| Change the base domain | Not supported in place — hostnames are baked into OIDC redirect URIs. Redeploy with the new domain and recreate the Authentik providers |
| Rotate an OIDC client secret | Update it in Authentik **and** the matching `.env`, then restart that service |
| Rotate the OnlyOffice JWT secret | Update `FILEBROWSER_ONLYOFFICE_SECRET` and the OnlyOffice `JWT_SECRET`, then restart both |
| Rotate `sogo-sso.pass` | Automatic: it regenerates on every Dovecot restart |
| Add disk space | Grow the volume, then `docker system prune` for dangling images — **never** prune volumes |
| Inspect the broker's transfers | Read the broker audit log at `user-data/broker/audit.log` |

## 10. Upgrading

### 10.1 Workcenter

```bash
git checkout Stable && git pull origin Stable
./setup.sh              # reconfigure anything new, then bring the stack up
# or, for a code-only change:
docker compose up -d --build workcenter
```

Read [`CHANGELOG.md`](./CHANGELOG.md) first. Anything under `Notes` may require action.

### 10.2 Mailcow

> **Mailcow is updated only with its own script.** Workcenter never edits Mailcow's compose file, so
> `update.sh` continues to work and Workcenter's changes survive in the untracked override.

```bash
cd Mailcow
./update.sh
```

Before updating, back up ([§11](#11-backup-and-restore)). After updating, re-check that
`HTTP_REDIRECT=n` and the other Workcenter settings survived — `update.sh` merges upstream changes
into tracked files, and `mailcow.conf` is tracked upstream.

### 10.3 Other applications

| Application | How |
| --- | --- |
| FileBrowser Quantum | Change `FILEBROWSER_IMAGE` in `.env` to the new pinned tag, then `docker compose up -d filebrowser`. Review the upstream changelog for config-schema changes — v2 decoding is strict, so a new required key breaks startup loudly |
| Zulip | Change the Zulip image tag, rebuild the derived image, `docker compose up -d`. Follow docker-zulip's upgrade notes; secrets stay stable |
| OnlyOffice | Change `ONLYOFFICE_IMAGE`, then `docker compose up -d onlyoffice` |
| Authentik | Change `AUTHENTIK_TAG`, then `docker compose up -d`. Migrations run automatically on first start; watch the `server` logs |
| Traefik | Change `TRAEFIK_TAG`, then `docker compose up -d traefik` |

### 10.4 Upgrade order

1. Back up.
2. Read the changelogs of everything you are bumping.
3. Authentik, then Traefik, then the applications, then Workcenter last.
4. Verify with `docker compose ps` and the [integration matrix](./integration.md#12-integration-verification-matrix).

## 11. Backup and restore

### 11.1 What must be backed up

| Path | Contents | Sensitivity |
| --- | --- | --- |
| `Mailcow/data/` and Mailcow's named volumes | Mail, mailboxes, configuration | **High** |
| `Zulip/data/`, `Zulip/database/` | Chat history and uploads | **High** |
| `Filebrowser/data/` | Users, shares, the index | Medium |
| `${FILEBROWSER_SOURCE_PATH}` | The actual user files | **High** |
| `Authentik/data/postgres/` | Identity, groups, providers | **High** |
| `Traefik/acme.json`, `Traefik/certs/` | Certificates and keys | **High** |
| `user-data/` | Workcenter config and the broker token store | **High** |
| Every `.env` and `*/secrets/` | Secrets | **High** |

> **Note:** `acme.json` and everything under `*/secrets/` must be backed up encrypted and with
> restrictive permissions. A backup containing plaintext secrets is itself a security incident if lost.

### 11.2 Backup procedure

```bash
# 1. Stop application writes (Mailcow first, safest)
(cd Mailcow && docker compose stop)
docker compose stop

# 2. Dump the databases
(cd Mailcow && docker compose exec -T mysql-mailcow \
   mysqldump --all-databases --single-transaction --routines > /backup/mailcow.sql)
docker compose exec -T authentik-postgresql-1 \
   pg_dump -U authentik authentik > /backup/authentik.sql
docker compose exec -T zulip-database-1 \
   pg_dump -U zulip zulip > /backup/zulip.sql

# 3. Sync the tree (config, secrets, bind-mounted data)
rsync -aHAX --delete \
  --exclude '.git' --exclude 'node_modules' --exclude 'dist' \
  /srv/workcenter/ /backup/workcenter/

# 4. Restart
docker compose start
(cd Mailcow && docker compose start)
```

Retain at least **three** generations, one of them off-host.

### 11.3 Restore procedure

```bash
# 1. Restore the tree to a clean host with Docker installed
rsync -aHAX /backup/workcenter/ /srv/workcenter/
cd /srv/workcenter

# 2. Bring up only the databases
(cd Mailcow && docker compose up -d mysql-mailcow)
docker compose up -d authentik-postgresql zulip-database

# 3. Restore the dumps
(cd Mailcow && docker compose exec -T mysql-mailcow mysql < /backup/mailcow.sql)
docker compose exec -T authentik-postgresql psql -U authentik authentik < /backup/authentik.sql
docker compose exec -T zulip-database psql -U zulip zulip < /backup/zulip.sql

# 4. Bring the whole stack up
./setup.sh

# 5. Verify
docker compose ps
```

### 11.4 Restore drill

A restore that has never been tested is not a backup. Run a drill at least quarterly on a disposable
host, and record the date and outcome in [`CHANGELOG.md`](./CHANGELOG.md) under `Notes` if the
procedure changed.

## 12. Internal TLS between backend services

By default, service-to-service traffic stays on the Docker `internal` network in plaintext. Where
policy requires encryption in transit, Workcenter can enable internal TLS.

```bash
# In .env
ENABLE_INTERNAL_TLS=true
INTERNAL_CA_CN="Workcenter Internal CA"
```

`setup.sh` then:

1. Generates an internal CA and a leaf certificate per service with SANs for the Docker service names
   (`filebrowser`, `onlyoffice`, `zulip`, `nginx`, `authentik-server`).
2. Writes them into `Traefik/certs/`.
3. Switches inter-service URLs from `http://` to `https://`.
4. Mounts the CA into the Workcenter container and sets `NODE_EXTRA_CA_CERTS` so the broker trusts it.
5. Adds a Traefik `serversTransport` with the CA configured for the affected routers.

| Ref | Rule |
| --- | --- |
| P-23 | Internal TLS is **opt-in**, and the generated CA private key is stored in `Traefik/certs/` and gitignored. |
| P-24 | Never disable certificate verification to make internal TLS work. For OnlyOffice over self-signed HTTPS, use a Traefik `serversTransport` with the CA — not `insecureSkipVerify`. |
| P-25 | Applications that cannot validate a private CA are left on the internal network without TLS, and the exception is recorded in [`docs/security.md`](./docs/security.md). |

## 13. Health, monitoring and logs

### 13.1 Health

```bash
docker compose ps
(cd Mailcow && docker compose ps)
./scripts/healthcheck-all.sh           # one-shot
./scripts/healthcheck-all.sh --wait    # poll until healthy or timeout
```

| Service | Check |
| --- | --- |
| Workcenter | `/healthz` |
| FileBrowser Quantum | `/health` → `{"message":"ok"}` |
| ONLYOFFICE | `/healthcheck` |
| Zulip | `/health` — IP-restricted; the prober must be in `SETTING_LOADBALANCER_IPS`, or it gets **403** |
| Authentik | `/-/health/live/`, `/-/health/ready/`; worker `ak healthcheck` |
| Traefik | `/ping` on the `traefik` entrypoint |
| Mailcow (container states) | `GET /api/v1/get/status/containers` with the **`X-API-Key`** header — a **read-only** key (`API_KEY_READ_ONLY`) is accepted for status calls. Response is an object keyed by service name whose values have exactly five fields (`type`, `container`, `state`, `started_at`, `image`); **there is no `health` field**, so *healthy* means **every `state == "running"`** |
| Mailcow (liveness) | `GET https://mail.example.com/` returning **200**. Mailcow's `prerequisites.inc.php` hard-exits 500 when Redis, MariaDB **or** `dockerapi` is down, so a 200 proves `nginx → php-fpm → Redis → MySQL → dockerapi` are all alive. Probe **HTTPS** — port 80 returns 301 |
| Mailcow (aggregate) | `docker compose ps` as the fallback |

### 13.1a Reading Mailcow's health correctly

Mailcow is the one component where "is it healthy?" needs care.

| Fact | Consequence |
| --- | --- |
| Mailcow's `docker-compose.yml` defines **zero** `healthcheck:` blocks | Do **not** gate on `.State.Health` for Mailcow services |
| `condition: service_healthy` appears **four times** — on `clamd`, `postfix`, `postfix-tlspol` and `acme` — and always gates on **`unbound-mailcow`** | `unbound-mailcow` is the **only** Mailcow-built image with a baked `HEALTHCHECK`. It is not a proxy for overall stack health |
| `sogo`, `nginx`, `dovecot`, `postfix` and `phpfpm` declare no `HEALTHCHECK` | Treat them as healthy when the container is `running` **and** `.RestartCount` is not increasing |
| `docker compose ps -a --format json` emits **JSONL** — one object per line, not an array | `healthcheck-all.sh` must parse line-by-line, not as a single JSON document |
| Mailcow's real health system is **`watchdog-mailcow`**, which probes `/SOGo.index/` and restarts services after `SOGO_THRESHOLD` (3) consecutive failures | **It restarts silently** unless you set `WATCHDOG_NOTIFY_WEBHOOK` and `WATCHDOG_NOTIFY_WEBHOOK_BODY`. Set them so Mailcow pushes health events into Workcenter's monitoring |

A robust per-container check is therefore:

```bash
docker inspect --format '{{.Name}} {{if .State.Health}}{{.State.Health.Status}}{{else}}none{{end}} {{.State.Status}} restarts={{.RestartCount}}' \
  $(docker ps -q --filter label=com.docker.compose.project=mailcow-dockerized)
```

| Ref | Rule |
| --- | --- |
| P-26 | Never gate a Mailcow service on `.State.Health`. Use `.State.Status` plus a non-increasing `.RestartCount`, or the Mailcow API's `state` field. |
| P-27 | Set `WATCHDOG_NOTIFY_WEBHOOK` so Mailcow's silent restarts become visible. |
| P-28 | Include `https://mail.example.com/` returning 200 in the health script — it is the single cheapest end-to-end proof that Mailcow's web tier is intact. |

### 13.2 Logs

```bash
docker compose logs -f --tail=200                 # all Workcenter-managed services
docker compose logs -f workcenter                 # shell + broker
docker compose logs -f --tail=100 zulip
(cd Mailcow && docker compose logs -f postfix-mailcow)
```

Log rotation is configured per service in the compose files with `logging.options.max-size` and
`max-file`. Do not rely on unbounded Docker logs — Mailcow is chatty.

### 13.3 What to alert on

| Signal | Meaning |
| --- | --- |
| Any service `unhealthy` for > 5 minutes | A dependency is failing |
| `acme.json` unchanged for > 60 days with an expiring certificate | ACME renewal is broken |
| Traefik 5xx rate rising | An upstream is failing |
| Mailcow watchdog notification | Mailcow's own alerting — act on it |
| Broker audit log showing repeated failures | An integration credential has expired |

## 14. Troubleshooting

Ordered by likelihood.

### 14.1 Sign-in

| Symptom | Cause | Fix |
| --- | --- | --- |
| Redirect loop | The issuer URL includes `/.well-known/openid-configuration` | Use the bare issuer |
| Redirect loop, issuer looks right | Authentik advertises `http://` behind Traefik | Set `AUTHENTIK_LISTEN__TRUSTED_PROXY_CIDRS` and forward `X-Forwarded-Proto: https` |
| `invalid redirect URI` | URL mismatch — scheme, host, or trailing slash | Register both variants with `Strict` matching |
| Login succeeds, no groups | The `profile` scope is missing, or `Include claims in id_token` is off | Emit `groups` from the `profile` scope and enable claims in the id_token |
| Login rejected with an email-verification error | `email_verified` defaults to `False` in recent Authentik | Map or override the claim |
| 403 after login | The user is not in `workspaceusers` | Add them, or remove `userGroups` |

Full table: [`OIDC.md` §12](./OIDC.md#12-troubleshooting).

### 14.2 Panes

| Symptom | Cause | Fix |
| --- | --- | --- |
| "Refused to connect" on the Chat pane | Zulip's `X-Frame-Options: DENY` | Confirm you are running the derived Zulip image, not the upstream one |
| A pane shows a login page | The application's session expired | **Sign in again**; for Mail, this must go through the Mailcow UI |
| Chat pane loads but never updates | Traefik buffering or timing out the long-poll | Disable response buffering on the event route and extend read/idle timeouts |
| Files pane is empty for a new user | `config.defaultEnabled` is false on the source | Set it to `true` and restart FileBrowser |

### 14.3 Mail

| Symptom | Cause | Fix |
| --- | --- | --- |
| Traefik → Mailcow gives infinite redirects | `HTTP_REDIRECT=y` | Set it to `n` in `mailcow.conf` and recreate `nginx-mailcow` |
| Port 80/443 already in use | Mailcow's own listeners | Set `HTTP_BIND`/`HTTPS_BIND=127.0.0.1` |
| Mailbox login fails under Generic-OIDC | No attribute mapping, or a missing mail domain | Configure the mapping; create the domain |
| IMAP/SMTP fails after OIDC | Mail protocols do not use OIDC | Create an **app password**, or enable Mailcow's LDAP provider |
| SOGo shows its own login form | No Mailcow SSO session | Use **Login to Webmail** in the Mailcow UI first |
| Attachments do not save to Files | The broker's source mount does not match FileBrowser's | Assert at startup; check `FILEBROWSER_SOURCE_PATH` |
| Mailcow broke after an update | The override or `mailcow.conf` was overwritten | Re-apply, then re-run `./setup.sh` in configure-only mode |

### 14.4 Editing

| Symptom | Cause | Fix |
| --- | --- | --- |
| Documents open read-only | JWT secret mismatch between FileBrowser and OnlyOffice | Make `FILEBROWSER_ONLYOFFICE_SECRET` and `JWT_SECRET` byte-identical, restart both |
| The editor never loads | `integrations.office.url` is not reachable from the browser, or the router denies framing | Check the URL from a browser; remove `frameDeny` from the OnlyOffice router and set `accesscontrolalloworiginlist=*` |
| Callbacks fail | OnlyOffice cannot reach `/api/office/callback` | Ensure `http.internalUrl` is set and the callback paths are excluded from any forward-auth middleware |

### 14.5 Stack-wide

| Symptom | Cause | Fix |
| --- | --- | --- |
| A service restarts in a loop | Config error — FileBrowser v2 decoding is strict | `docker compose logs <service>`; an unknown key is fatal |
| Out of memory | Undersized host | Add RAM or swap; see [§2.1](#21-host) |
| Disk full | Docker images and logs, or mail | `docker system prune`; review Mailcow retention |
| `setup.sh` fails at a prompt in CI | A required value is missing | Every prompt has an environment-variable equivalent; see [`OIDC.md` §9](./OIDC.md#9-environment-variable-reference) |

## 15. Uninstalling

```bash
# Stop everything (keeps data)
docker compose down
(cd Mailcow && docker compose down)

# Remove images (keeps data)
docker compose down --rmi local

# DESTRUCTIVE: remove Mailcow's named volumes (mail loss)
(cd Mailcow && docker compose down -v)

# Remove the deployment tree
cd .. && rm -rf workcenter
```

> **Warning:** deleting the tree deletes the bind-mounted data — mail, chat, files, identity and
> certificates. Back up first, and revoke the OIDC providers and DNS records afterwards.

## 16. Production checklist

Before you call a deployment production-ready:

- [ ] Deployed from `Stable`, not `Dev`.
- [ ] DNS for all six hostnames resolves, and ports 80/443 are reachable.
- [ ] Mail DNS is complete: `MX`, SPF, DKIM, DMARC, and a PTR record.
- [ ] TLS certificates issued for all six hostnames; `acme.json` is `chmod 600`.
- [ ] `docker compose ps` shows every service healthy.
- [ ] A `workspaceusers` member can sign in and reach all three panes.
- [ ] A `workspaceadmin` member can reach the Traefik dashboard; a non-admin cannot.
- [ ] All four file-movement flows work end to end.
- [ ] Mailcow's Traefik routing has **no** redirect loop (`HTTP_REDIRECT=n`).
- [ ] Mailcow updated successfully at least once with `./update.sh`, and the override survived.
- [ ] Every `.env` and `*/secrets/` file is gitignored and backed up encrypted.
- [ ] A restore drill has succeeded on a disposable host.
- [ ] Log rotation is configured and Docker's disk use is bounded.
- [ ] `Ignore SSL Errors` and any `disableVerifyTLS` setting are **off**.
- [ ] No service is published directly to the internet except Traefik and Mailcow's mail ports.
- [ ] The Zulip role sync has been re-run after any group change (`./setup.sh`).
- [ ] [`CHANGELOG.md`](./CHANGELOG.md) has been reviewed for `Notes` that require operator action.
